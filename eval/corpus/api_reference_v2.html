Nimbus API Reference

Version 2.4 · Last updated: 2023-09-12

The Nimbus REST API lets you automate workspace administration, user management and file operations. All endpoints are served over HTTPS from https://api.nimbus.example/v2 and return JSON.

Authentication

Every request must include an API key in the Authorization header using the Bearer scheme, for example Authorization: Bearer nmb_live_xxx. API keys are created by workspace admins in the Admin Console.

Basic authentication with a username and password is also supported for legacy integrations, but API keys are recommended for all new integrations.

Rate Limits

The API allows 100 requests per minute per API key. Requests above this limit are rejected with HTTP status 429 and the error code ERR-429. The response includes a Retry-After header that tells the client how many seconds to wait before retrying.

Bulk endpoints count as one request regardless of how many records they return. Rate limits are applied per API key, not per workspace, so separate integrations should use separate keys.

Endpoints

Workspaces

GET /v2/workspaces lists the workspaces the API key can access. POST /v2/workspaces creates a new workspace and requires the Owner role.

Users

GET /v2/users lists users in a workspace. POST /v2/users/invite sends an invitation email. DELETE /v2/users/{id} removes a user and transfers their files to the workspace owner.

Pagination

List endpoints return at most 50 items per page. Use the next_cursor value from the response to request the following page. A missing next_cursor means there are no more results.
